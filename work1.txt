Домашнее задание 1
Темы:

Архитектура и структура проекта в Django.
Работа с базами данных и ORM в Django.
CRUD и REST API в Django.

Цель задания: закрепить навыки проектирования архитектуры веб-приложения, разработки серверной логики, работы с базами данных, организации REST API и подготовки проекта к деплою на разных технологических стеках.

Инструменты для выполнения: Python, Django, Django REST Framework, FastAPI, PostgreSQL / SQLite, Django ORM / TypeORM, Postman.

Правила приёма работы:

Код должен быть написан на языке Python с применением фреймворков Django, Django REST Framework, отвечать требованиям PEP 8 и покрыт комментариями.
Код проекта должен быть декомпозирован на функции, методы, классы, модули.
Проект должен быть логически структурирован.
Проект должен разворачиваться с использованием Docker.
Проект должен содержать README-файл с краткой информацией о проекте.

 
Общая информация о проекте
На протяжении дисциплины «Серверные фреймворки бэкенд-разработки» мы будем разрабатывать единый веб-проект, который реализуется двумя серверными фреймворками:

в домашнем задании 1 вам предстоит реализовать проект на Django;
в домашнем задании 2 — на NestJS.
Описание проекта
Вам необходимо реализовать систему управления бронированием мастер-классов (Workshop Booking System).

Требования к функциям системы — пользователи системы смогут:

просматривать список мастер-классов;
регистрироваться на участие;
просматривать свои бронирования;
добавлять новые мастер-классы (для пользователя с ролью администратора).
Процесс реализации
В домашнем задании 1 серверную часть приложения вы создаёте на Django с Django REST Framework, в домашнем задании 2 вы переписываете её на NestJS, сохраняя ту же структуру API и бизнес-логику.

 

Домашнее задание 1
Реализуйте систему управления бронированием мастер-классов (Workshop Booking System). Серверная часть проекта должна быть создана на Django с Django REST Framework.

Требования к серверной части (Django):

спроектируйте архитектуру приложения (модели, контроллеры, сервисы);
реализуйте REST API для всех операций;
создайте модели данных и связи между сущностями (Users, Workshops, Bookings);
реализуйте CRUD-операции для мастер-классов и бронирований;
реализуйте базовую аутентификацию пользователей и авторизацию (для ролей администратор и пользователь);
используйте ORM (Django ORM или TypeORM);
реализуйте сериализацию и валидацию данных.
Требования к клиентской части:

взаимодействие с сервером через REST API;
отображение списка мастер-классов и информации о них;
возможность записи на мастер-класс;
управление своими бронированиями;
обработка ошибок и состояний загрузки данных.
На выбор*: настройте тестирование через Postman или создайте клиент на Next.js.

*Задание базовой сложности — настроить тестирование через Postman, задание повышенной сложности — создать клиент на Next.js. Необходимо выполнить одно из двух заданий (оба задания в одном проекте выполнять не нужно). 

Минимальная функциональность системы:

регистрация и авторизация пользователей;
просмотр мастер-классов;
создание бронирований;
просмотр своих бронирований — для пользователя;
CRUD мастер-классов — для админа.
Технологический стек:

Django + Django REST Framework
PostgreSQL или SQLite
JavaScript / TypeScript + Next.js (опционально) или Postman

Критерии оценки домашнего задания 1 на защите
1. Модели данных и БД — 0-5 баллов:

созданы модели User (с ролями), Workshop, Booking;
настроены связи между моделями и ограничения (запрет повторов брони);
созданы и применены миграции.
2. Аутентификация и права доступа — 0-5 баллов:

работают регистрация и вход (выдача токена);
доступ к созданию бронирований есть только у авторизованных пользователей;
CRUD для мастер-классов — только для роли администратор;
пользователь видит только свои бронирования.
3. API — 0-10 баллов:

эндпоинты соответствуют REST-стандартам;
реализован публичный просмотр списка и деталей мастер-классов (GET);
реализован CRUD для мастер-классов (POST, PUT, DELETE) от имени администратора;
авторизованный пользователь может создать бронь (POST);
система проверяет вместимость мастер-класса (нельзя забронировать мест больше, чем ограничение системы);
авторизованный пользователь может посмотреть свои брони (GET) и отменять их (DELETE).
4. Сериализация и валидация — 0-5 баллов:

ответы API не содержат лишних полей (паролей, хешей);
данные возвращаются в формате JSON;
при просмотре бронирования подтягиваются данные мастер-класса;
есть защита от записи на прошедшие даты и дублирования брони.
5. Архитектура и ORM — 0-5 баллов:

код разбит на логические части (модели, контроллеры, сериализаторы);
используются select_related / prefetch_related для оптимизации запросов (борьба с N+1).
6. Работа с клиентом (базовая сложность) — 0-5 баллов:

создана коллекция Postman, покрывающая все эндпоинты;
в коллекции используются переменные и автотесты (проверка кодов ответа).
6*. Документирование API (повышенная сложность, дополнительные баллы) — 0-2 балла: вместо Postman создан клиент на Next.js с роутингом, загрузкой и обработкой ошибок. Обратите внимание: итоговая сумма баллов за домашнее задание 1 не может превышать 35 баллов, даже с учетом дополнительных баллов.

Важно: работа не принимается, если не работают основные эндпоинты (бронирование, просмотр) или в репозитории отсутствует README-файл с краткой информацией о проекте.
